### 1. 토스트가 `<b>`·`<br>` 를 글자 그대로 찍는다 — v9.192·v9.200·v9.201 안내 5곳
`showToast` 는 `msgEl.textContent = msg` (index.html `function showToast` 안, "msgEl.textContent" grep).
그런데 아래 호출들은 HTML 을 넣는다 → 사용자에게 **`<b>공유로 이미지가 넘어오지 않았어요</b>`** 처럼 태그가 그대로 보인다.
- 25172 새 버전 안내(v9.192) — `<b>프롬프트 랩</b> → <b>새로고침</b>`
- 25199 공유 실패 안내(v9.200) — `<b>…</b>` + `<br><span style=…>받은 것: …</span>`
- 17690 HEIC 안내(v9.201) — `<b>HEIC 사진</b>`
- 17744 끌어다 놓기 실패 안내(v9.201) — `<b>그림을 못 찾았어요</b>` + `<br><span …>`
- (grep `showToast([^)]*<b>` 로 전수 확인할 것 — 4건 + 새 버전 안내 1건)

**고치는 법(안전하게)**: `showToast` 에 `{ html: true }` 옵션을 두고 그때만 `innerHTML` 을 쓴다. 기본은 지금처럼 `textContent`.
⚠ **25199 의 `failInfo` 는 주소(`?info=`)에서 온 값이라 그대로 innerHTML 에 넣으면 XSS 다** — `_animaEsc(failInfo)` 로 반드시 escape
(17744 는 이미 `_animaEsc(info)` 를 쓴다). 검사: `sharemime-test`·`dropin-test` 의 토스트 확인을 `textContent` 에 `<b>` 가 **없는지**로 바꾼다.

### 2. 공유 경로만 '그림인지' 확인을 안 한다 — 받는 곳 기준 불일치 (v9.201.0 원칙 위반)
- `sw.js:127` — 후보 ③ `cand.find(v => isBlob(v) && v.size > 0)` 는 **어떤 파일이든** 받고, `sw.js:147` 에서 `Content-Type` 을 `image/png` 로 적는다.
- `_plConsumeShared` 는 그걸 그대로 `_animaSetImage(dataURL)` 에 넣는다 — `_animaSniffImage`·`_animaCanDecode` 를 **안 거친다**.
- 끌어다 놓기(`_animaTakeBlob`)는 둘 다 거친다. → PDF 를 공유하면 공유 경로는 "이미지를 넣었어요" 뒤에 깨진 원본이 되고, 끌어다 놓기는 "그림을 못 찾았어요"가 뜬다. **같은 파일에 두 화면이 다르게 답한다.**
- 고치는 법: `_plConsumeShared` 가 blob 단계에서 `_animaTakeBlob(blob, name)` 을 타게 한다(지금은 `_plShareInit` 에서 dataURL 로 바꿔 넘기므로, dataURL 대신 blob 을 넘기거나 `_plShareInit` 안에서 sniff 한다). HEIC 도 그러면 공유 경로에서 같은 안내가 뜬다.

### intake — 이미지가 들어오는 4갈래 (반박 검증 전 · 1번은 위 ✅2 와 같은 것)
- **[high]** 공유 경로만 그림 검증(sniff/decode/HEIC)이 없다 — `sw.js:126` ③후보가 아무 파일이든 받아 `image/png` 로 적고(147행), `index.html` `_plShareInit` 의 blob→dataURL 구간(≈25231~25246)이 검사 없이 `_animaSetImage` 로 넘긴다. PDF·HEIC·동영상을 공유하면 "이미지를 넣었어요" 뒤에 깨진 원본. → ✅2 와 동일. **한 곳(`_animaTakeBlob`)으로 합칠 것.**
- **[medium]** 공유 캐시를 **꺼내는 쪽**이 다시 조용해진다 — `?shared=1` 로 왔는데 `c.match` 가 null 이거나 `r.blob()`/FileReader 가 던지거나 `caches.open` 이 던지면(저장소 축출·quota) `index.html:25246` 안쪽 `catch (e) {}` 와 25260 바깥 `catch (e) {}` 가 삼키고 `if (!out.length) return` 으로 **아무 안내 없이 앱만 뜬다.** v9.200.0 이 없앤 '조용한 실패'가 sw.js 쪽만 없어지고 앱 쪽엔 남았다. → 여기서도 `why=read`/`store` 급 안내를 띄울 것.
- **[medium]** 붙여넣기(`onPaste`, `index.html:21176`)·📋 클립보드(`_animaClipboard`)는 MIME 만 보고 HEIC/디코드 불가를 검증 없이 넣는다 — 끌어다 놓기와 기준 불일치. → 둘 다 `_animaTakeBlob` 을 타게 하면 끝난다(위와 같은 처방).
