# 의상 프리셋 추가 가이드 (다른 AI에게 넘길 시안)

> 프롬프트 랩의 **「추천」 패널 → 👗 의상** 축에 새 프리셋을 넣을 때 지킬 것.
> 이 축은 🎲(생성할 때마다 굴리기)가 **전체 풀에서** 뽑으므로, 쓸모없는 항목은 그대로 낭비가 된다.

---

## 1. 파일과 형식

| 파일 | 무엇 | `_meta.tier` |
|---|---|---|
| `data/looks-danbooru.json` | 일반(SFW) 42개 | `base-sfw` |
| `data/looks-nsfw.json` | 성인(19+) 147개 | `adult` |

```json
{
  "_meta": { "count": 147, "nsfwCount": 147, "kind": "outfit-looks", "tier": "adult" },
  "outfits": [
    { "n": "화이트 블라우스 오피스룩",
      "tags": ["white blouse", "pencil skirt", "dress shirt", "unbuttoned", "pantyhose"],
      "nsfw": true }
  ]
}
```

- `n` — **한글 이름**. 기존과 겹치면 안 된다.
- `tags` — **영문 danbooru 태그 배열**.
- `nsfw` — 파일의 tier 와 맞춘다(`adult` 파일은 전부 `true`).
- ⚠ 항목을 더하면 **`_meta.count` / `nsfwCount` 도 함께 고칠 것.**

---

## 2. 절대 규칙 6개

### ① 문장을 쓰지 말 것 — 태그 배열만
앱이 `importPromptToEditor(tags)` 로 **태그를 하나씩 분류해 계층에 넣는다.**
문장은 사전에 없어서 **5계층(액션)으로 떨어지고**, 의상이 액션 칸에 들어가도
**오류가 안 나서 조용히 망가진다.**

### ② 실제로 존재하는 danbooru 태그만
①과 같은 이유다. 지어낸 말은 계층 분류에 실패한다.
`velvet` `satin` `sheer` `glossy` `iridescent` `latex` `mesh` 처럼 **실제 태그인 재질어**를 쓴다.

### ③ 몸을 바꾸는 태그 금지 — 착용물로 번역할 것
`slime girl` `monster girl` `dragon horns` `cow ears` `mecha musume` 같은 것은
**신체를 변형**시켜서 실사 머지(Pony Realism 등)에서 뭉개진다.
**사람 몸은 그대로 두고 의상만 그 컨셉으로** 바꾼다.

| ✗ 이렇게 말고 | ✓ 이렇게 |
|---|---|
| `dragon horns, dragon tail, scales` | `horned headpiece`, `scale armor`, `iridescent` |
| `cow ears, cow horns, cow tail` | `cow print`, `bell collar` (무늬는 옷이라 잘 나온다) |
| `slime girl, monster girl` | `translucent bodysuit`, `glossy`, `dripping` |
| `mecha musume, mechanical parts` | `armored bodysuit`, `pauldrons`, `gauntlets` |

### ④ 기존 프리셋과 태그 겹침 0.6 미만 (자카드)
겹치면 🎲로 굴려도 **같은 그림**이 나와 한 장이 통째로 낭비된다.
실제로 겹침 **1.00**(태그가 글자까지 동일)인 짝이 있어서 지웠다.

### ⑤ 태그 4~9개 (현재 평균 6.4개)
2~3개면 굴려도 아무것도 안 바뀐다. 10개를 넘으면 앞 75토큰 예산을 먹는다.

### ⑥ 상위 개념 태그를 쓰지 말 것
`halloween costume` `casual outfit` 같은 건 실사 머지에서 **그림에 더하는 게 거의 없다.**
그 자리에 **재질·색·실제 옷 이름**을 넣는다.

## 3. 좋은 예 3개

```json
{ "n": "할로윈 섹시 마녀",
  "tags": ["(witch costume:1.2)", "purple and black", "velvet", "wide brim hat",
           "witch hat", "off-shoulder dress", "lace trim", "thighhighs", "high heels"],
  "nsfw": true }
```
→ 상위 태그 대신 **재질(velvet) + 색(purple and black)**. 같은 할로윈이라도
악마는 `latex` + `red and black`, 뱀파이어는 `satin` + `crimson and black` 으로 **확실히 벌렸다.**

```json
{ "n": "드래곤 걸",
  "tags": ["(scale armor:1.3)", "horned headpiece", "iridescent", "metallic",
           "winged cloak", "bikini armor", "loincloth", "thigh boots", "gauntlets"],
  "nsfw": true }
```
→ 뿔이 **나는** 게 아니라 뿔 장식을 **쓴다**. 비늘이 돋는 게 아니라 비늘 갑옷을 **입는다**.

```json
{ "n": "캐주얼 데일리룩",
  "tags": ["shirt", "jeans", "sneakers", "cardigan", "casual"],
  "nsfw": false }
```
→ SFW 는 단순해도 된다. 서로 다른 옷 이름이 겹치지 않게 들어가 있으면 충분하다.

## 4. 나쁜 예 3개

```json
{ "n": "웻룩 경기 수영복", "tags": ["competition swimsuit", "highleg", "wet", ...] }
```
✗ 「하이레그 경기 수영복」과 **태그가 글자까지 같았다**(겹침 1.00). 굴려도 구분이 안 된다.

```json
{ "n": "가슴골 오픈셔츠룩", "tags": ["open shirt", "cleavage"] }
```
✗ 태그 2개. 굴려도 아무것도 안 바뀌고, 「오픈셔츠룩」과도 중복이었다.

```json
{ "n": "리본 액세서리룩", "tags": ["ribbon", "hair ribbon"] }
```
✗ **의상이 아니라 머리 장식**이다. 의상 축에 들어갈 것이 아니다.

---

## 5. 가중치

`(tag:1.2)` ~ `(tag:1.3)` 을 **프리셋당 최대 1개**, 그 옷을 그 옷이게 하는 **핵심 하나**에만.
전부 같은 무게면 무엇이 중요한지 모델이 모른다. 앱이 괄호와 숫자를 벗겨 내고 분류하므로 안전하다.

```bash
node tests/looks-test.js
```

이게 보는 것:
- 이름 중복 · `_meta.count` 일치
- **태그 겹침 0.6 이상인 짝이 없는가**
- 태그 2개 이하가 없는가
- **새 태그를 앱이 전부 아는가** ← 모르면 5계층으로 새서 조용히 망가진다
- 가중치가 붙어도 같은 계층으로 가는가
- **실제로 담아 봤을 때 의상(4계층)이 액션(5계층)보다 많은가**

`adult_optin_v1` 만으로는 안 실려서, 강화한 항목이 통째로 '없음'으로 나온다.
